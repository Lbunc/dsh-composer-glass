# 位移图几何：三个陷阱与应对

这份笔记记录的是**与 DSH、与 Cordis 都无关**的通用知识 ——
任何"用位移图做背景折射"的实现（canvas/WebGL、OffscreenCanvas、
或将来的原生 `backdrop-filter: url()`）都会撞上同样三个坑。

每个坑都是实测踩出来的，附可复现的检测方法。

---

## 背景：位移图做什么

`feDisplacementMap`（或任何等效实现）按下式偏移采样：

```
dst(x, y) = src(x + (R(x,y)/255 - 0.5) * scale,
                y + (G(x,y)/255 - 0.5) * scale)
```

所以位移图里 **0.5 = 不偏移**，比 0.5 小 = 向负方向拉，比 0.5 大 = 向正方向拉。
做透镜效果时，希望"越靠边、采样越向内收"，于是 R/G 在边缘应偏离 0.5，
在中心应恰好 0.5。

---

## 陷阱 1：宽高比

**现象**：边缘折射弱到几乎看不见，但图本身"看起来是对的"。

**原因**：把图拉伸进元素盒子时，**profile 不会同步缩放**。
在宽高比 `A_map` 下设计的 profile，渲染到 `A_el` 的元素上，
水平分量会被除以 `A_el / A_map`。

**量级**：参考实现用方形 profile。放到 5.7:1 的宽条上，
水平折射损失约 5.3 倍 —— 实测 R 偏移 0.365 → 0.069。

**应对**：位移图**必须按目标元素宽高比生成**。

**检测**：拿一张正方形 profile 的图，放到极扁的容器里。
如果水平方向几乎没变化而垂直方向很明显，就是这个坑。

---

## 陷阱 2：折射带位置

**现象**：垂直方向整片糊，水平方向**完全没有**折射。

**原因**：圆角矩形 SDF 的半宽/half-height 是在**归一化空间**里定的。
缩放进一张宽图后，半宽会远小于图的半宽，于是 SDF 边界落在离图边很远的地方 ——
**左右边缘根本没进入圆角半径**，sink 恒为某个中间值甚至饱和。

实测：SDF 半宽 37.8px，图半宽 255px，差了近 7 倍。

**应对**：不要用"圆"。两条边带**各自绑定自己的轴**，用椭圆场：

```js
d = ((|px|/HALF_X)^k + (|py|/HALF_Y)^k)^(1/k) - 1
```

宽元素需要**宽的横向带 + 窄的纵向带**，圆表达不了，椭圆可以。
`k` 控制圆角程度（`k→0` 纯椭圆，`k→1` 接近直角）。

**检测**：沿水平中线扫 R，沿垂直中线扫 G。
如果只有一族有变化，就是这个坑。

---

## 陷阱 3：归一化

**现象**：边缘带**没有对比度**，整片呈现同一个偏移量 —— 看起来像"模糊"
而不是"透镜"。这正是"只有毛玻璃感"的来源之一。

**原因**：位移图通常要归一化（除以某个 max）。
三种错误做法：

| 做法 | 后果 |
|---|---|
| 两通道共享一个 max | 宽图里垂直位移远大于水平，水平通道被压成硬截断 |
| 用全局 max（含角落） | 角落位移是边缘中点的数倍，边缘中点被压到 0.5 附近 |
| 用理想值而非实测值 | 几何换算极易出错，实测与预期差 17% 甚至更多 |

**应对**：
1. 两个通道**各自**归一化。
2. 归一化基准取**实测的边缘中点位移**，不是全局 max。
3. 允许角落过冲出界饱和 —— 那圈过冲正好是四角的亮珠。
4. **写盘后解码自己的 PNG 做校验**，不要相信账面推导。

**检测**：解码 PNG，看中间行有多少像素顶在 0 或 255。
超过一半就是带没了对比度。

---

## 可复用的自检代码

写盘后解码并断言，任一不过就报错退出。
这比调试视觉现象快一个数量级 —— 图中坏掉时脚本直接失败。

```js
// 读回 PNG（8-bit RGBA、非隔行、filter type 0）
const raw = inflateSync(Buffer.concat(idat))
const R = (x, y) => raw[y * (stride + 1) + 1 + x * 4]
const G = (x, y) => raw[y * (stride + 1) + 1 + x * 4 + 1]

const my = (h / 2) | 0, mx = (w / 2) | 0

// 1. 中心必须无偏移
assert(Math.abs(R(mx, my) - 127.5) <= 6, '中心偏移了')

// 2. 边缘中点必须有明显位移，且左右对称
assert(Math.abs(R(0, my) - 127.5) > 12, '左边缘几乎不位移：带太窄')
assert(Math.abs(R(w - 1, my) - 127.5) > 12, '右边缘几乎不位移：带太窄')
assert(Math.abs(R(0, my) + R(w - 1, my) - 255) <= 8, '左右不对称')

// 3. 中间行不能有大量饱和（否则边缘带失去对比度）
let saturated = 0
for (let x = 0; x < w; x++) {
  const r = R(x, my)
  if (r === 0 || r === 255) saturated++
}
assert(saturated <= w * 0.5, `${saturated}/${w} 饱和：归一化基准错了`)
```

实测通过时的读数（512×90，边缘 42% 位移）：

```
  left edge mid   :  74
  right edge mid  : 181
  centre          : 128     ← 必须 ~127
  saturated       :   0 / 512
```

74 与 181 关于 128 对称，说明几何正确且未饱和。

## 与 `scale` 的耦合（最容易忽略的一点）

`feDisplacementMap` 的**实际**位移 = `通道偏移 × scale`，
而通道偏移是**元素尺寸的比例**（因为默认 `objectBoundingBox` 单位）。

推论：
- 同一张图在任意尺寸的元素上**自动等比缩放**，不用重生成。
- 但 **`scale` 与位移图强绑定**：图变了，`scale` 必须重算。

实测：边缘偏移从 0.07 提到 0.42 后，同样的边缘位移所需 `scale`
从约 22 变成约 96。**只调参数不换图，永远调不出效果。**

近似公式：

```
scale ≈ 目标边缘位移(px) / 通道偏移量
通道偏移量 ≈ (边缘归一化值 - 0.5) / 2
```

---

## 一句话总结

位移图坏掉时**不会报错**，只会安静地渲染成一片糊。
所以**必须**在生成侧自检 —— 把"看起来不对"变成"脚本报错退出"。
